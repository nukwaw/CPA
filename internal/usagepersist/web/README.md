# Embedded statistics and navigation asset

This package, under `internal/usagepersist/web`, contains the dependency-free statistics page and the navigation asset that links the management sidebar to it. It has no npm dependencies, network fonts, CDN scripts, or generated frontend bundle. The page is served at `/stats.html`; its assets use the single canonical `/stats-assets/*` namespace exported as `AssetsPrefix`. The navigation asset (`management-nav.js`, marker `data-cpa-stats-nav`, `window.CPAStatsNav`) adds the sidebar entry that opens the page.

The page and the sidebar entry are deliberately decoupled from the upstream management panel's internals. Injection (`InjectManagementNav`) only places one `<script>` tag before the first original script; it never recognizes, patches, or wraps the upstream build, so a panel update cannot hide the sidebar entry or break the dashboard. The asset itself also tolerates unknown sidebar markup: an unrecognized sidebar is left unchanged and the dashboard stays reachable by URL.

## Server integration

- Serve `Asset("stats.html")` at `/stats.html` and the four JavaScript/CSS assets at `/stats-assets/:name`, retaining the returned MIME type and sending `X-Content-Type-Options: nosniff`.
- Management APIs remain behind the existing management authentication middleware at `/v0/management/stats`. Static assets contain no credentials.
- Apply `ManagementNavMiddleware` (or call `InjectManagementNav` equivalently) to the in-memory `GET /management.html` response, not the updater's file on disk. The document is augmented regardless of storage availability: the dashboard itself reports an unavailable store. A successful augmentation sends `X-CPA-Stats-Nav: enabled`, `Cache-Control: no-store`, removes source validators/checksums and range advertisement, and repairs the content length. Partial, encoded, overflowing, flushed, and error responses retain their original bytes. Inference requests, streaming, and WebSocket routes are not intercepted.

## Authentication and safety

The statistics page sends a management key in `Authorization: Bearer ...` only to its same-origin API. By default the key stays in memory. The optional checkbox saves it to `sessionStorage` for that browser tab; disconnect clears it. The dashboard does not read/decode the management application's saved password and never puts secrets in URLs. Existing server cookies, if supported by the host, use same-origin credentials.

The navigation asset never reads the management key. The link is a plain anchor: every click, plain or modified, keeps its native behavior and opens the dashboard, which asks for the management key itself. The entry is added to the `aside.sidebar .nav-section` markup, is re-added idempotently after a sidebar re-render, leaves the page unchanged when that markup is absent, and is the only DOM node this add-on adds.

All model/provider/error text is rendered with DOM text APIs, never raw HTML. CSV cells protect against spreadsheet formula execution.

## Statistics behavior

Persistence passively consumes the original built-in CPA usage provider's already-gated payload; it is not a separately enabled collection feature. The existing `usage-statistics-enabled` setting (v8: `observability.usage.usage-statistics-enabled`) retains its original behavior and reload controls. `USAGE_PG_DSN` selects an independently owned usage-only PostgreSQL pool, with optional `USAGE_PG_SCHEMA`. Without it, standalone runs use an instance-local journal under the existing `WRITABLE_PATH`/auth directory conventions. CPA configuration/authentication storage is not changed, and there is no additional collection toggle.

Storage initializes independently of inference startup. Usage and management observations enter a bounded asynchronous queue of 256 sanitized records plus at most one in flight; optional storage I/O does not block those callbacks. Overflow, write errors, and shutdown cancellation can lose observations, and there is no durable retry spool. The native journal supports at most 64 MiB and 100,000 unique events, without pruning retained history. These are supported storage limits, not exact process-RSS guarantees; decoding and concurrent queries need headroom.

The dashboard reads `collection_enabled` from `/v0/management/stats/status`. When it is explicitly `false`, an informational notice explains how to resume built-in collection. Previously stored history, pricing, and quota remain available while storage is healthy, and the notice does not disable filters, refresh, exports, or pricing actions. Storage-write failures and bounded-ingestion `dropped_events` are shown together with the collection notice; drop warnings include queue-overflow and validation-failure counts. Pending admissions are informational and may include the one in-flight event in addition to the bounded queue. There is no new collection toggle. Missing health fields from an older status response do not imply disabled collection or data loss. An unavailable storage response (`available: false` or HTTP 503) explicitly warns that persistence is unavailable while the original management page and manual quota refresh remain available.

The page has four tabs: **Overview** (merged totals line, traffic chart, composition, and the model/provider performance tables), **Requests** (the live request stream), **Quota** (one saved-state card per attributable credential plus a per-credential side window), and **Pricing & sync**. Overview and Requests share explicit date/model/provider/result filters; there is no header statistics strip and there is no credential or API key ID filter or column, because per-credential traffic is reached through the quota side window. One preset list — Today, Yesterday, Last 24 hours, Last week, Last month, Custom range, All retained history — drives every range control the page owns, including the side window's, so the two can never offer different choices; the markup is empty and the list is rendered into it, and Today is the default. The calendar presets resolve to the reader's local day boundaries, matching the frame the page labels its buckets in, and a day boundary is built from calendar parts rather than by subtracting a fixed 24 hours so a DST shift cannot move it; the rolling presets measure back from now. All-history queries supply an explicit epoch lower bound instead of relying on the backend's last-24-hours default. Charts use timestamp spacing and label downsampled series; newest data is retained. Requests shows newest-first, paginated completed executions. Polling pauses for hidden/offline pages, older request pages, a paused stream, and a paused side window, and backs off on errors. A failed update preserves the prior snapshot with a visible warning rather than replacing it with misleading zeros.

`stats.css` carries no design system of its own: it reuses the control panel's, because this page is injected into that panel and a second visual language would read as a seam. Tokens, the 14px hairline card, the near-black pill action, the monospaced numerals and the categorical series colours mirror CPAMC's `white` theme, and the dark theme mirrors its `dark` tokens; the panel's colours are used with the panel's meaning, so green marks success and healthy headroom, amber the middle band, and `#c65746` the warning edge. An empty quota card presents the panel's dashed "click here to refresh" pad instead of explaining itself in prose. Categorical series colours live in CSS as `--series-1`…`--series-5` and are referenced by name from `stats.js`, so the palette is defined in exactly one place.

Each request entry carries its own detail instead of a credential column: the requested model and provider, the reported response model (flagged on the entry and its row when it differs from the requested one), the requested and reported service tier (flagged when they differ), total tokens, throughput, cache read share, latency, first-token time, and cost. Throughput is complete output tokens over total request time and cache read share is cache reads over input tokens, both matching the keeper dashboard and both shown as unknown rather than zero when the base is absent. A failed execution exposes its sanitized bounded provider message as a hover/focus detail on the result badge; the dashboard never renders the stored text as markup.

The Quota tab reads `/quota`, `/quota/cache`, and the existing management auth-files list together and reduces every provider's saved state shape — Claude windows, Kimi rows with untranslated keys and used/limit counters, grouped buckets, billing objects, or a normalized snapshot fallback — to the same labelled percentage line. A saved window and a normalized window for the same limit are matched by their mapped ids, so a newer observation replaces that window's value instead of adding a second line, while a window the newer observation does not carry keeps its saved value. An absent value stays absent instead of rendering as zero, and a credential without saved windows explains how to populate them. Selecting a card — the card itself, not only the action on it — opens a modal side window for that credential. The card is only clickable when it can open that window, so the affordance never appears on a card with nothing to show, and a click on one of the card's own buttons belongs to that button rather than also opening the window.

Quota reaches the backend without any browser-side adapter and without any quota machinery of its own: the core producer stamps account facts on provider rate-limit header samples (the only observation the add-on normalizes itself, for the Codex and Claude header families), and the control panel's own display state arrives through `PUT /quota/cache`. The add-on holds no provider endpoint knowledge, no credential projection, and no middleware tee. Manual refreshes triggered from the dashboard's Quota tab ask the existing management quota handler to run; that handler owns provider quota (plugin providers, credential probes, and its builtin provider endpoints), and it reports every successful fetch back through an explicit observer the adapter registers, which records the result under the credential's account facts. The `PUT /quota/cache` endpoint remains available for authenticated management API clients; its freshness fencing is unchanged.

The side window carries **Quota** and **Requests** as two tabs rather than stacking both on one surface, because they are two independent reads that happen to describe the same credential. Quota holds the recorded window history and the estimated value of the requests attributed to the credential; Requests holds the credential's own stream, newest first, and its pause control, which belongs to that stream. Only the visible tab is read, so a reader stays on one endpoint at a time, and pausing the stream does not stop the quota tab refreshing. Opening the window always starts on Quota. The window selector and the range selector are shared because both tabs are scoped by them. The range selector offers the same presets as the page filters and defaults to Today; picking Custom range reveals the side window's own From/To inputs, and an incomplete or inverted range reports itself on the surface rather than silently reading nothing. The window selector defaults to automatic, which charts the window the server reports as most observed. An explicit choice sends the backend window id the value was recorded under, which is not always the display id the card renders ("five_hour" against "5h limit"): only ids a line can name are offered, each labelled as the card labels it, so every choice charts history and no window is listed twice under two names. The selected range drives the history, the value estimate, and the stream. The credential key is displayed as its file name; the internal NUL-separated suffix is never rendered.

Prices are USD per million tokens, not provider invoices. The fixed Models.dev sync source preserves manual overrides. Unknown prices remain unpriced; missing catalog cache rates are not displayed as free. The catalog can contain thousands of rows, so rendering is limited to the first 200 search matches with an explicit notice. Search still covers every downloaded model rate. Storage-health warnings identify potential gaps after persistence failures.

## Quota fidelity

Live credential files come from the existing authenticated `GET /v0/management/auth-files`: each entry contributes only its `name`, `provider`, `email` and transient `auth_index`. The entry's `account` field is never read, because it can carry an API key. A card is keyed by `(provider, name)`: **one card per credential file**, which is the unit the control panel's own quota page uses (Devin keeps its filename + NUL + auth-index composite key). Two credentials that publish one account stay two cards, because they are two credentials that can each be refreshed, and a credential that publishes no account keeps its own card instead of being merged with an unrelated credential that also publishes none. The account stays a recorded fact on each card: it is titled by its credential file, with the account, provider and last observation shown as detail. The account fact still scopes the side window, so `(provider, account)` remains usable for filtering and grouping without keying the cards. Durable state stays keyed by `(provider, account)`, so a credential file can be renamed without orphaning its saved history. `auth_index` is the transient request-start correlation value only: it is never persisted, never used as a map key, and is sent only to the existing management quota handler when asking it for a provider refresh.

The identity GET also primes the server's immutable advisory publication. Original management handlers read that publication without touching the live credential manager; the independent worker revalidates captured evidence authoritatively. A manager read lock can cover core storage I/O, so no live lookup is allowed on the shared usage callback or original-handler chain. An original management request arriving before an explicit identity read may skip optional observation; it is never delayed waiting for it. There is no background refresher.

The core producer stamps the account facts where the live credential is known, so a header sample is attributed by provider and account: account-labeled Codex and Claude credentials attribute their rate-limit headers, and a same-account token rotation keeps updating the same state. A credential that publishes no account property has empty account facts; it is grouped under its provider alone and is attributed there rather than dropped. No token is ever part of the attribution. Newer eligible normalized observations from `/quota` can overlay known windows without refreshing unrelated values. The floor for that comparison is the observation time of the value already displayed: the session's own observation when it has one, otherwise the stored display state's `observed_at`. A mapped newer window without `reset_at` clears that window's old reset timestamp and label/hint instead of mixing fresh usage with an expired display-cache reset. The backend already retains valid future resets where appropriate; the adapter never invents a refill or a reset time. Unrelated windows and stale incoming observations are left unchanged. Codex and Claude have verified normalized-to-display mappings, including Codex additional-limit windows matched uniquely by observed name and duration. Durationless Codex observations are not guessed as five-hour or weekly. Other providers' successful rendered caches hydrate, but normalized windows whose identities cannot be mapped unambiguously are ignored rather than assigned to the wrong card.

## Tests

```sh
node --test internal/usagepersist/web/web_test.cjs
go test ./internal/usagepersist/web
CPA_MANAGEMENT_FIXTURE=/path/to/upstream/dist/index.html go test ./internal/usagepersist/web ./internal/usagepersist ./internal/api
output="$(mktemp -t cpa-web-build)" && go build -o "$output" ./cmd/server && rm "$output"
```

The built-in-module [Node regressions](web_test.cjs) cover health/capacity notices, filters/charts/pricing, CSV and DOM safety, per-credential-file cards (two auth files of one `(provider, account)` stay two cards, an account-less credential never merges with another, and the auth-files `account` field is never read), the statistics sidebar entry (idempotent mount, unknown markup, plain-anchor click behavior, no key access), and the tab-scoped key storage. The optional `CPA_MANAGEMENT_FIXTURE` checks prove a real upstream single-file build — of ANY version — receives the navigation asset unchanged except for the one injected `<script>` tag. [Middleware tests](../management_middleware_test.go) additionally cover pre-upgrade 304 handling, restored request identity, inference-route isolation, ranges/preconditions, compressed bytes, overflow, and error fallbacks.
